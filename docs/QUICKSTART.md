# BULLIT — как дать другу поиграть (и чтобы фиксы подтягивались сами)

Коротко: **пришли другу игру один раз**. Дальше он просто запускает
`bullit.exe` — игра **сама** проверяет GitHub при старте, качает твой свежий
билд и перезапускается обновлённой. Батник не нужен. Играете вдвоём: в одной
локалке игра **находит хоста сама**, через интернет — по VPN + IP.

Ниже — три части: (A) один раз настраиваешь ты, (B) один раз получает друг,
(C) как играть каждый раз.

> Никакого лаунчера/батника друг запускать не обязан — самообновление встроено
> в игру. Папка `tools/launcher/` осталась как запасной вариант (если вдруг
> захочется обновлять отдельным лаунчером), но по умолчанию она не нужна.

---

## A. Настройка у тебя (хост) — один раз

1. **Запушить репозиторий на GitHub** (remote уже `Fijekronk/bullit`).
   Если имя другое — поправь `$Repo` в `tools/launcher/launcher.ps1`.
2. Репозиторий уже **публичный** — игра берёт релизы с GitHub без токена.
   (Если сделаешь приватным — см. конец файла про токен.)
3. **Один раз создать ветку `playtest`** — сборки идут с неё:
   ```
   git checkout -b playtest
   git push -u origin playtest
   ```
4. Открой вкладку **Actions** на GitHub → дождись зелёного прогона →
   в **Releases** появится `playtest-<дата>-<коммит>` с файлом `bullit_win.zip`.
   Это и есть готовый билд, который заберёт лаунчер.

### Как выкатывать фиксы (каждый раз, когда что-то починил)

Твоя рабочая ветка сейчас — `network`. Чтобы фикс дошёл до друга, отправь её
в `playtest`:
```
git push origin network:playtest
```
GitHub соберёт новый билд и опубликует релиз. **Больше ничего делать не надо** —
у друга обновление подтянется при следующем запуске лаунчера.

> Если ветка `playtest` разошлась и push ругается — можно перезаписать:
> `git push origin network:playtest --force` (это плейтест-ветка, не main —
> перезапись безопасна).

## B. Получение игры другом — один раз

1. Скачай сам из GitHub Releases файл `bullit_win.zip` (или зайди в Actions →
   готовый билд) и **пришли другу** (или дай ссылку на релиз — репо публичный).
2. Друг распаковывает zip в любую папку (напр. `C:\BULLIT`) — внутри
   `bullit.exe` и `version.txt`.
3. Всё. Дальше он запускает **`bullit.exe`** — игра сама обновляется при
   каждом старте. Больше ничего присылать не нужно, даже при твоих фиксах.

## C. Как играть — каждый раз

### 1. Поднять общую сеть (VPN)
Прямой проброс портов НЕ нужен. Проще всего **Radmin VPN** (бесплатно, обоим):
1. Оба ставят https://www.radmin-vpn.com
2. Ты: «Создать сеть» → задаёшь имя и пароль → сообщаешь их другу.
3. Друг: «Присоединиться к сети» → вводит имя+пароль.
4. В окне Radmin виден **твой IP** вида `26.x.x.x` — он понадобится другу.

(Альтернатива — Tailscale: оба ставят, IP хоста вида `100.x.x.x`.)

> **В одной локальной сети (один роутер/Wi-Fi) VPN не нужен вообще** — игра
> найдёт хоста сама (см. ниже). VPN нужен только через интернет.

### 2. Запустить игру
- Оба запускают **`bullit.exe`** (двойной клик). Игра проверит обновление,
  при необходимости обновится и перезапустится, затем откроет **меню**:
  ник, роль (Полевой / Вратарь), кнопки.

### 3. Соединиться
- **Ты (хост):** нажми «**Хостить игру**» (порт 9050). Ты сразу в матче.
- **Друг — в одной локалке:** ничего вводить не нужно. Через пару секунд
  внизу появится зелёная кнопка «**▶ Играть в локалке: <твой ник>**» —
  нажимает её и попадает к тебе.
- **Друг — через интернет (VPN):** в поле «IP хоста» вводит **твой Radmin-IP**
  (`26.x.x.x`) → «**Подключиться**».
- В буллите 1v1 роли противоположны: кто выбрал вратаря — стоит в воротах,
  второй атакует. Хост может поменять роли клавишей **F3** между раундами.

### Управление в сети
- **WASD** — движение (относительно камеры), **мышь** — разворот камеры.
- **F2** — панель «Сеть» (пинг/RTT, трафик, задержка интерполяции).
- **Esc** — выйти в меню (у клиента рвёт коннект, у хоста закрывает сервер).
- Полный список действий — `docs/CONTROLS.md`.

## Частые вопросы

- **Как игра обновляется?** При старте `bullit.exe` сверяет свой `version.txt`
  с последним релизом на GitHub. Если вышло новое — качает `bullit_win.zip`,
  распаковывает во временную папку и запускает служебный скрипт, который ждёт
  выхода игры, копирует новые файлы поверх и открывает игру заново. Друг видит
  только «Обновление… перезапускаю». Никаких батников он не трогает.
- **Обновление не подтянулось** — ты ещё не пушил в `playtest` или сборка на
  GitHub не закончилась (проверь зелёный прогон в Actions). Игра сверяет
  `version.txt` с тегом релиза: совпали — качать нечего.
- **Нет интернета у друга** — игра не упадёт: тихо пропустит проверку и
  запустится на текущей версии.
- **Друг не видит игру в локалке** — авто-поиск работает в пределах одной
  подсети (один роутер/Wi-Fi). Если вы в разных сетях/через интернет — заходите
  по IP (VPN). Файрвол может блокировать UDP-маячок (порт 9051) и сам коннект
  (9050) — при первом запуске разреши игре сеть в окне Windows Firewall.
- **Инпут-лаг** — в v1 нет предсказания, задержка = ваш пинг. В локалке ~0,
  по VPN внутри Европы ~20–50 мс. Ограничения — `docs/NETWORK.md`.

### Приватный репозиторий (если снова сделаешь приватным)
GitHub API без токена не отдаёт релизы приватного репо. Тогда самообновление
из коробки не сработает (в игре токен не зашит специально — чтобы не утёк).
Варианты: держать репо публичным (сейчас так) ИЛИ обновлять отдельным
лаунчером `tools/launcher/launcher.ps1`, дописав в `$Headers` строку
`Authorization = "Bearer <fine-grained token, только чтение Releases>"`.

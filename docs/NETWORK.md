# BULLIT — сеть v1 (listen-server, серверный авторитет)

Играть вдвоём через интернет: один хостит (он же сервер+игрок), второй
подключается по IP. Архитектура: Godot High-Level Multiplayer + ENet,
listen-server, строгий серверный авторитет («сервер решает — клиент показывает»).

## Как соединиться через интернет (VPN)

Прямой проброс портов не нужен — поднимите общую виртуальную сеть.

### Вариант A — Radmin VPN (проще)
1. Оба качают Radmin VPN (бесплатно): https://www.radmin-vpn.com
2. Хост: «Создать сеть» — задаёт имя и пароль, сообщает их другу.
3. Друг: «Присоединиться к сети» — вводит имя+пароль.
4. В списке сети виден IP хоста (вида 26.x.x.x). 
5. Хост в игре: Меню → Хост (порт 9050). Друг: Меню → Подключиться →
   вводит IP хоста : 9050 → Подключиться.

### Вариант B — Tailscale
1. Оба ставят Tailscale (бесплатно), логинятся одним способом (или шарят сеть).
2. Хост смотрит свой Tailscale-IP (100.x.x.x) в трее/`tailscale ip`.
3. Друг подключается на этот IP : 9050.

Проверка локально (одна машина): запустить два экземпляра, второй Join на
`127.0.0.1:9050`.

## Меню и управление в сети
- Игра стартует с **главного меню** (ник, роль, Хост / Подключиться /
  Тренировка / Выход). Хост создаёт сервер (порт 9050) и сразу играет;
  второй вводит IP хоста и жмёт «Подключиться».
- **Авто-поиск в локалке**: хост шлёт UDP-broadcast-маячок (порт 9051); в меню
  у клиента в той же подсети появляется кнопка «▶ Играть в локалке: <ник>» —
  IP вводить не нужно. Через интернет/VPN broadcast не проходит — по IP.
- **Самообновление**: exe при старте тянет свежий билд с GitHub (см.
  docs/QUICKSTART.md) — в редакторе пропускается.
- **F2** — панель «Сеть» (RTT, вх/исх Б/с, размер снапшота, задержка
  интерполяции, номер последнего применённого тика ввода).
- **F3** (только хост) — смена ролей игроков (применяется со следующего вброса).
- **Esc** — выйти в меню (у клиента рвёт соединение, у хоста закрывает сервер).

## Буллит-петля 1v1
Атака до гола / вылета шайбы → сервер засчитывает очко (ровно один раз) →
пауза 3 c → вброс в центр, игроки на стартовые половины. Счёт вверху экрана
у обоих. Роли меняются хостом по F3 между раундами.

## Роли: полевой и вратарь
В буллите 1v1 роли противоположны: хост выбирает роль в меню, второй
автоматически получает другую (полевой ⇄ вратарь). Вратарь управляется как
обычный игрок (WASD относительно камеры, мышь — разворот), Пробел — баттерфляй,
A/D в бабочке (дабл-тап) — пуш к штанге, ЛКМ/ПКМ — ловушка/блин. Хост меняет
роли по **F3** между раундами.

Технически: сервер разворачивает вратаря пира по присланному **yaw камеры**
(у пира на сервере своей камеры нет); клиент держит куклу-вратаря, которая
локально проигрывает процедурную позу из синхронизированного состояния
(стойка/баттерфляй/падение) — плавно, без «телепорта» поз.

## Что синхронизируется (30 Гц снапшоты)
- Игроки: позиция, facing, velocity.
- Шайба: позиция, velocity, состояние (FREE/CARRIED/AIR/GLOVED).
- Вратарь: позиция, разворот, состояние машины поз, флаги ловушки/блина.
- Голы/счёт/вбросы/смена ролей — reliable RPC-события.

Клиент шлёт на сервер ТОЛЬКО пакет ввода (InputState.make_packet): вектор
WASD/зажатия — unreliable_ordered каждый тик; дискретные рёбра (клики,
финты, пробел, Q/E) — в том же пакете с номером тика.

## Честные ограничения v1
- **Инпут-лаг = RTT**: клиентского предсказания НЕТ. По VPN внутри Европы
  RTT ~20–50 мс — играбельно для теста. Предсказание+реконсиляция локального
  игрока — следующий сетевой этап (после того, как поиграете и соберёте
  ощущения).
- Интерполяция клиента ~100 мс (плавность важнее задержки), без экстраполяции.
- Читозащиты нет (доверенная пара), но серверная валидация ввода (клампы,
  частота пакетов) — базово есть. Все параметры в сети фиксированы серверными
  (панель тюнинга не синхронизируется).
- 1v1 (макс 2 игрока), без матчмейкинга/выделенного сервера/чата.

## Полный путь доставки билда (для плейтеста)
Пуш в ветку `playtest` → GitHub Actions собирает Windows-билд → релиз →
лаунчер друга обновляется (см. docs/BUILDS.md) → друг заходит по VPN-IP хоста.
